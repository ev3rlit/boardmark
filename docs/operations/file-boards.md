# Desktop 파일 보드 사용

파일 보드는 desktop에서 사용한다. 웹의 DB Markdown 모드와 기존 `.md` 모드는 유지된다. `.boardmark.json`은 기존 DB 문서 이동용 묶음이며 여기서 다루는 `.boardmark`와 다르다.

실행: 저장소 루트에서 `corepack pnpm dev`. 빌드 확인: `corepack pnpm --filter @boardmark/desktop build`.

1. 왼쪽 **탐색기 → 프로젝트 폴더 열기**로 작업 폴더를 선택한다. 폴더를 누르면 트리에서 펼치거나 접는다. 방향키로도 탐색할 수 있다.
2. 생성할 부모 폴더를 선택하고 탐색기의 **새 파일** 또는 **새 폴더**를 누른다. 폴더 우클릭 메뉴도 같은 동작을 제공한다. 트리 안에서 이름을 입력하고 Enter로 생성하며, Escape 또는 입력창 밖으로 포커스를 옮기면 취소한다. 파일이 선택된 경우 그 파일의 부모 폴더에 만든다. 저장 위치를 다시 묻지 않는다. `.boardmark` 파일은 유효한 빈 보드로 생성해 열고, `.md` 등 다른 파일은 빈 파일로 생성한다. 일반 파일 편집기는 이번 범위에 포함하지 않는다. 같은 이름이 있으면 덮어쓰지 않고 이름을 고칠 수 있게 오류를 표시한다. 전용 폴더나 프로젝트 등록 파일은 필요 없다.
3. 기존 화이트보드의 **New note**로 메모를 만들고 기존 인라인 편집기로 작성한다. 기존 선택, 이동, 크기 변경, 연결, 도형, 그룹, 색상, Undo/Redo를 사용한다.
4. 기존 **Image → 파일 선택** 흐름으로 원본 이미지를 고른다. 이미지 바이트를 보드에 넣거나 별도 첨부로 복사하지 않는다. 파일 드롭도 같은 참조 경로를 사용한다. 원본 파일이 없는 클립보드 이미지는 파일로 저장한 뒤 선택한다.
5. **보드 저장** 또는 기존 파일 메뉴의 **Save**로 저장한다. 메모 편집 초안도 함께 반영한다. 파일 보드는 명시적으로 저장하며, 미저장 상태는 위쪽에 표시한다.
6. 앱을 다시 실행하여 같은 프로젝트 폴더와 보드를 연다. 마지막 프로젝트·보드를 자동으로 여는 기능은 포함하지 않는다.

`design/overview.boardmark`에서 `../assets/reference.svg`를 참조하면 실제 이미지는 `assets/reference.svg`에 있다. 보드에는 메모 내용·항목 배치·이미지 경로·연결이 있고, 이미지 원본은 별도 파일이다. 프로젝트 전체를 이동해 내부 위치가 유지되면 같은 참조가 동작한다. 다른 드라이브의 이미지는 상대 경로로 표현할 수 없어 추가를 거절한다. 누락된 이미지는 해당 항목에 오류를 표시하며 다른 항목은 계속 편집할 수 있다. 이미지 배치를 삭제해도 원본 파일은 삭제하지 않는다.

저장 전에 외부 변경을 확인한다. 변경이 있거나 쓰기가 실패하면 기존 파일과 현재 초안을 보존하고 오류를 표시한다. 저장은 같은 폴더의 임시 파일을 쓰고 동기화한 다음 교체한다. 다른 프로그램과 동시에 쓰는 상황에서 운영체제 전체의 독점 잠금을 보장하지는 않는다. 앱 밖에서 보드 파일만 옮긴 경우 경로 자동 추적은 하지 않는다.

포맷의 유일한 기준은 [`schemas/boardmark.schema.json`](../../schemas/boardmark.schema.json)이다. 타입과 실행용 검증기는 `corepack pnpm generate:board-types`로 생성한다. `corepack pnpm typecheck`는 생성물이 스키마와 일치하는지도 확인한다. 포맷 구조를 이 문서에 별도로 정의하지 않는다.

예제: [`examples/file-board/design/overview.boardmark`](../../examples/file-board/design/overview.boardmark). `examples/file-board`를 프로젝트로 열면 메모와 상대 이미지 참조, 연결선을 확인할 수 있다.

UI 실행 확인은 사용자가 담당한다. 최종 확인 항목은 [검증 기록](../verification/file-boards.md)에 있다.
