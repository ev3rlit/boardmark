# DB Markdown와 공통 편집 API

상태: 로컬 단일 서버 구현 (2026-09-09). 실제 실행 결과와 한계는 [검증 보고서](../verification/db-workspace.md)에 기록한다. 이 문서는 기존 파일 원본·extension-first 설명을 DB 관리 모드에 한해 대체한다.

## 확정된 제품 계약

웹 GUI와 AI CLI는 공통 API를 사용한다. DB의 Markdown 원문 문자열만 문서의 최종 원본이다. AST와 검색 모델은 읽을 때 다시 만들 수 있다. 문서 ID와 표시 이름은 분리한다. `.md`는 가져오기·내보내기 수단이며 외부 수정 자동 동기화는 하지 않는다. desktop·VS Code의 파일 모드는 별개 문서를 소유하는 호환 모드다.

## 초기 구현 선택 (사용자 확정 요구와 구분)

- Node.js 24 내장 HTTP 서버와 `node:sqlite`를 사용한다. 기존 TypeScript 실행 환경과 맞고 별도 DB 서비스·네이티브 모듈 설치가 필요 없다. Node.js 24를 실행 기준으로 고정한다. SQLite는 단일 서버·로컬 사용 범위이며 다중 서버 배포는 지원하지 않는다.
- SQLite에 Markdown, 문서 버전, 처리 요청, 변경 이력, 편집권 발급 세대와 첨부 바이트를 보관한다. WAL과 FULL 동기화, 짧은 쓰기 트랜잭션으로 정책 검증과 저장을 묶는다. 편집 중에는 트랜잭션을 열어 두지 않는다.
- JSON 요청/응답과 버전 기반 변경 확인 채널을 분리한다. 클라이언트는 확정 버전보다 새로운 변경만 읽고 재연결 시 최신 상태를 조회한다. 전송 방법은 초기에는 주기적인 변경 확인을 사용한다. WebSocket·Redis는 필요하지 않다.
- 기본 바인딩은 127.0.0.1이다. 로컬 접근 토큰과 세션별 식별자로 API 접근 및 편집권 소유자를 구분한다. Origin 검사와 개발 프록시를 사용한다. 원격 계정·인증 서비스는 후속 범위다.

## 편집과 충돌 계약

객체 단위 명령을 최신 원문에 적용한다. 기존 compiler/resolver를 GUI와 독립적인 패키지로 분리한다. 읽기 기준은 문서 버전과 함께 반환한다. 서버는 그 버전의 대상과 최신 대상 및 관련 구조를 비교한다. 다른 객체 변경만 있으면 적용하고, 대상 또는 관계가 바뀌면 최신 상태와 재계산 정보를 반환한다. 클라이언트가 기준 버전을 몰래 최신으로 바꾸면 안 된다.

편집권은 객체별 독점 임시 권한이다. 실제 편집 시작 시 자동 확보하고, 정상 세션은 갱신하고, 마지막 저장 후 반납한다. 30초 유효기간, 10초 갱신을 출발값으로 한다. 세션 종료·단절은 만료로 회수한다. 10분 동안 입력이 없는 편집은 초안을 보존하고 권한을 반납한다. CLI 대기는 제한 시간·취소를 지원한다.

2026-09-09 사용자 요청에 따라 드래그·리사이즈는 **클라이언트 예측 미리보기**를 사용한다. 첫 이동부터 화면 좌표·크기를 즉시 바꾸면서 편집권을 요청하며, 승인 전에는 문서 원문이나 확정 좌표를 변경하지 않는다. 승인 전에 포인터를 놓으면 미리보기를 유지하고 승인 후 한 번 저장한다. 대기 중 Escape·pointercancel·화면 종료는 취소이며 늦은 승인으로 저장하지 않는다. 거절·연결 실패 시 최신 확정 좌표로 복원하고 실패 이유를 알린다. 대기·저장 중 같은 캔버스의 다음 드래그를 쌓아 두지 않는다. 이는 기존의 ‘승인 전에 시각적 이동도 제한’ 정책을 대체한다. 서버의 편집권·버전 검증과 본문 편집 진입 정책은 유지한다.

서버가 명령 영향 범위를 계산한다. 다중 객체는 한 번에 전부 확보하거나 실패한다. 삭제는 연결선과 그룹 관계를 포함하며 연결선 생성은 양 끝 노드를 보호한다. 전체 교체·삭제는 문서 전체 범위와 정확한 문서 버전을 요구한다. 임시 권한은 Markdown에 쓰지 않는다. 재시작 시 발급 세대를 올려 이전 권한을 무효화한다.

요청 ID와 요청 내용·결과를 같은 트랜잭션에 영속화한다. 같은 ID의 같은 요청은 확정 결과를 다시 반환하고 다른 내용은 오류다. 성공 응답은 COMMIT 후에만 보낸다. 편집권 만료/충돌/오래된 기준/잘못된 명령/연결 실패를 구분한다. 동일 요청 재전송과 AI 변경안 재계산은 별개 동작이다.

## 보존과 복구 경계

읽기·가져오기·무수정 내보내기는 원문을 다시 직렬화하지 않는다. UTF-8 BOM·CRLF·주석·frontmatter·무관한 본문을 보존한다. 본문 변경은 해당 source range만 바꾼다. 객체 속성 변경은 대상 헤더를 JSON으로 직렬화하므로 그 헤더의 공백·키 순서는 바뀔 수 있지만 알 수 없는 최상위 속성 값과 무관한 구간은 남긴다. 객체 추가에는 구분용 줄바꿈을 삽입하고 삭제는 그 객체 범위를 제거한다. 삭제 Undo는 복원 블록을 문서 끝에 붙일 수 있어 원래 블록 순서·경계 공백까지 동일하다는 보장은 없다.

포맷이 해석하지 못하는 중첩 style 속성, 중복·누락 ID, 잘못된 관계는 편집 전에 오류로 보고한다. 원문 조회와 내보내기는 가능하다. 읽기 작업으로 포맷을 고치거나 ID를 새로 넣지 않는다. 명시적인 ID가 재파싱·저장·재접속 후 객체 식별의 기준이다. 구형 헤더는 파서가 지원하는 범위에서 읽고, 수정한 헤더만 현재 JSON 문법으로 바뀐다.

첨부는 DB BLOB으로 보관해 백업과 확정 경계를 단순하게 한다. 자료는 내용 해시로 공유하고 문서 삭제로 제거하지 않는다. 내보내기 묶음은 Markdown 원문과 참조 첨부를 함께 담는다. 기존 상대 경로 자료는 가져오기 시 명시적으로 제공하며 파일을 이동·삭제하지 않는다.

브라우저 초안은 서버 확정 상태와 별도로 저장한다. 재동기화는 활성 편집기·선택·카메라를 보존한다. 권한을 잃은 초안은 자동 덮어쓰지 않고 재시도 또는 사본 내보내기를 제공한다. Undo/Redo는 대상의 전제를 검사하는 역변경으로 처리하며 전체 이전 문서를 덮어쓰지 않는다.

## 검증 경계

사용자가 지정한 공개 API·실제 SQLite·별도 CLI·웹 편집 흐름을 테스트한다. 기존 테스트/타입 검사/빌드의 기준선을 먼저 확보한다. 완료 증거와 미검증 항목은 별도 실행 보고서에 기록한다. 계획만으로 완료 처리하지 않는다.
