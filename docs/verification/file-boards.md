# 파일 보드 v1 검증 기록

2026-09-18, Windows desktop 대상.

## 시작 상태와 범위

시작 시 main 브랜치에 README, 서버 진입점, 웹 Vite 설정, DB 운영 안내, 비전 인덱스, 브라우저 측정 스크립트, Boardmark 스킬의 기존 수정과 신규 비전 문서가 있었다. 해당 변경은 덮어쓰거나 되돌리지 않았다. 기존 OpenAPI·편집기 구현은 유지했다.

변경 전 `corepack pnpm typecheck`, desktop 빌드, desktop/repository 관련 8개 테스트가 통과했다. 대형 번들, Sandpack 정적·동적 import 혼용, preload URL 해석 경고가 기존 빌드에도 있었다.

## 구현 확인

- JSON Schema에서 TypeScript 타입과 CSP에 맞는 실행용 검증기를 생성한다. 로드·저장·JSON 편집 명령에 같은 검증기를 사용한다. JSON 구문, 버전, 구조, 중복 ID, 없는 연결/그룹 대상 오류를 구분한다.
- desktop main이 실제 보드 파일을 읽고 교체 저장한다. DB에 편집 사본을 만들지 않는다. 이미지 선택은 Electron `webUtils.getPathForFile`로 원본 경로를 얻어 상대 참조를 만든다.
- JSON 전용 편집 명령이 보드 객체를 직접 수정한다. `board-scene.ts`는 기존 렌더러가 사용하는 장면 모델을 파생하며, 원문 복사에 필요한 실제 JSON 위치를 기록한다. 기존 Markdown 문서 파서나 Markdown 부분 수정기는 통하지 않는다.
- 최초 구현의 별도 보드 내부 화면은 사용자 지적 후 제거했다. 최종 구현은 기존 `CanvasApp`, `CanvasScene`, 도구 모음, 인라인 편집기, 선택/연결/리사이즈 컴포넌트를 그대로 사용한다.
- 디자인 토큰, 공통 CSS, 기존 화이트보드 컴포넌트에는 diff가 없다. 추가 CSS는 프로젝트 탐색·파일 상태 영역의 구조 배치만 다룬다.
- 사용자 피드백을 반영해 왼쪽 탐색기를 폴더 트리로 변경했다. 선택한 폴더 기준 인라인 파일/폴더 생성, 우클릭 메뉴, 방향키 탐색, 새로고침, 모두 접기를 제공한다. 새 파일 생성 시 저장 위치를 다시 묻지 않는다. 상단 새 파일 버튼과 Boardmark/초기 안내/기존 Markdown 전환 문구를 제거했다.

## 자동 검사

푸시 전 서버·웹 회귀 검사를 포함한 관련 18개 테스트 파일의 199개 테스트가 통과했다. 여기에는 다음 범위가 포함된다.

- 스키마와 생성 타입 일치, 실제 예제, JSON 직렬화/재열기, 잘못된 JSON/버전/구조.
- ID·연결 대상 검증, Windows 상대 경로와 다른 드라이브 거절.
- 실제 임시 디렉터리에서 저장/재열기, 프로젝트 이동 후 이미지 참조, 누락 이미지, 배치 삭제 시 원본 보존.
- 저장 교체 실패, 중복 파일 생성, 잘못된 저장, 외부 변경 시 기존 파일 보존.
- 기존 store 명령으로 메모 편집·이동·크기 변경·연결·색상·그룹·Undo/Redo·이미지 참조·명시적 저장·세션 재구성.
- 실패하거나 늦게 끝난 저장이 현재 초안을 덮어쓰지 않는지 확인.
- 기존 Markdown store, 편집 서비스, CanvasApp 회귀 검사.
- 탐색기의 선택 폴더/파일 부모 기준 생성, 인라인 이름 입력과 중복 오류 수정, 우클릭·키보드 탐색·취소. 실제 임시 폴더에 새 폴더/보드/일반 파일 생성, 원본 덮어쓰기 방지, Windows 예약 이름 및 경로 탈출 입력 거절.
- 새 파일·폴더 입력에서 바깥 클릭이나 Tab으로 포커스가 벗어나면 취소되는지 확인. Enter 생성과 오류 수정 흐름도 유지된다.

`corepack pnpm typecheck`, `corepack pnpm --filter @boardmark/desktop build`, `corepack pnpm --filter @boardmark/web build`가 통과했다. 기존 빌드 경고 외의 실패는 없다. `git diff --check`도 통과했다.

## 사용자 실행 확인 대기

사용자가 직접 실행 검증을 담당하겠다고 요청하여 Electron 실행·조작 검증을 중단했다. 변경 전 화면과 최초 별도 화면의 실행 기록은 최종 구현의 검증 근거로 사용하지 않는다. 최종 UI의 실행·화면 비교·앱 종료 후 재열기를 완료했다고 주장하지 않는다.

사용자 확인 순서:

1. 왼쪽 탐색기에서 프로젝트 폴더 열기 → 폴더 펼치기 → 선택한 폴더에서 새 폴더/파일 이름 입력 → Enter. 새 `.boardmark`가 위치 선택 대화상자 없이 그 폴더에 생성되어 열리는지 확인.
2. 기존 New note와 인라인 편집기로 메모 작성 → Image의 파일 선택으로 이미지 참조.
3. 기존 방식으로 두 항목 이동·크기 변경 → 연결선 생성 → 저장.
4. 앱 종료 후 다시 실행 → 같은 폴더·보드 열기 → 내용·참조·배치·연결 확인.
5. 검증용 이미지를 잠시 다른 이름으로 바꾸어 누락 표시와 나머지 메모 편집 확인.
6. 이미지 배치만 삭제한 뒤 원본 파일이 남는지 확인.
7. 기존 화이트보드 내부 UI/UX 및 시각 스타일이 유지되었는지 확인.

남은 범위: 외부 파일 이동 자동 추적, 마지막 작업 자동 열기, 다른 드라이브 절대 이미지 참조, 원본 파일 없는 클립보드 이미지의 자동 파일 생성, 모든 호스트 전환은 포함하지 않는다.
