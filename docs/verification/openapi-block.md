# OpenAPI 첫 통합 검증

검증일: 2026-09-18. Node 24.19.0, Windows, Chrome, 로컬 웹/API와 별도 임시 SQLite 작업 공간에서 확인했다.

## 시작 상태

`main`에서 시작했다. README, 서버 실행 설정, Vite 설정, DB 운영 문서, 브라우저 측정 스크립트, Boardmark 스킬의 기존 변경 6개를 보존했다. 작업 도중 추가된 제품 비전 문서 변경도 이 통합에서 수정하지 않았다.

변경 전 타입 검사와 전체 테스트 **52파일 / 414개**가 통과했다. OpenAPI 렌더러와 편집기 인식은 없었다. DB Markdown 원본 계약, 기존 fenced renderer와 특수 블록 편집 경로를 확인한 뒤 그 경로에 추가했다.

## 최종 자동 검증

| 검증 | 결과 |
| --- | --- |
| `corepack pnpm test` | **54파일 / 441개 통과** |
| `corepack pnpm typecheck` | 통과 |
| `corepack pnpm build:web` | 통과 |
| `git diff --check` | 공백 오류 없음 |

추가한 27개 테스트는 YAML/JSON, 구문·필수 구조 오류, 중복 YAML 키, 버전 거절, 내부·외부·없는 참조, JSON Pointer 이스케이프, 스키마 자기 참조와 YAML 별칭 순환, 공통 파라미터 재정의, 요청·응답 참조, 예제 속 `$ref` 리터럴, 원본 크기 제한, 레지스트리 연결·검색·오류 복구·HTML 비실행, 편집·붙여넣기·일반 코드에서 전환, 탐색 중 노트 드래그 방지를 다룬다.

기존 편집기 테스트에서 `act(...)`/`flushSync` 관련 경고가 나오지만 실패는 없다. 빌드는 Sandpack의 기존 정적·동적 import 중복과 500 kB 초과 청크 경고를 낸다. OpenAPI는 별도 lazy 청크로 생성되며 새 런타임 의존성은 추가하지 않았다. 빌드 이전 기준선은 별도로 실행하지 않았으므로 번들 전체의 크기 증감을 측정했다는 뜻은 아니다.

## 실제 웹 흐름

- UI로 검증용 문서와 노트를 생성했다. 원본 코드 입력 영역에 [반려동물 YAML 예제](../examples/openapi-pets.yaml)를 입력하고 저장했다. 제목·설명·GET/POST 목록을 확인했다.
- 검색어 GET/POST로 목록을 좁히고 엔드포인트를 펼쳤다. 공통 `id` 파라미터와 POST 요청 본문, GET 응답을 확인했다.
- GET의 `200 → content → application/json → schema → Pet → properties → parent`를 실제로 펼쳤다. **순환 참조 · 상위 구조와 동일** 표시가 나타나며 더 이상 반복되지 않았다.
- 제목을 더블클릭해 노트 편집에 진입하고 **OpenAPI 원본 편집**을 사용했다. 제목 수정·완료·저장·새로고침 뒤 수정한 제목을 확인했다.
- `openapi: [` 오류를 저장하고 새로고침했다. 보드가 유지되고 오류와 원본이 남았다. 같은 편집 버튼으로 정상 YAML을 다시 입력해 저장·새로고침 후 복구를 확인했다.
- 다른 검증 문서에서 OpenAPI 3.0.4 JSON을 포함한 **전체 코드 블록 하나를 클립보드로 붙여넣었다**. 즉시 특수 블록으로 표시되고 `GET /health` 탐색과 저장 후 새로고침을 확인했다.
- 브라우저 오류 수집에서 실행 오류가 없었다. 320px 폭 노트에서 목록과 입력을 확인했으며, 깊은 구조는 스크롤·보드 줌을 이용해 탐색했다.

초기 붙여넣기에서는 기존 편집기가 Markdown fence를 여러 문단으로 받아 저장이 거절됐다. 원인을 확인한 뒤 **완성된 OpenAPI 블록 하나**만 특수 블록으로 붙여넣는 처리를 추가하고 같은 흐름을 재검증했다. 일반 코드 블록의 언어를 OpenAPI로 바꾸는 경우도 blur 시 특수 블록으로 전환하도록 회귀 테스트를 추가했다.

## 검증 경계

지원하지 않는 버전·외부 참조·없는 내부 참조는 자동 테스트로 확인했다. 모든 오류 조합을 브라우저에서 반복하지 않았다. 대규모 명세 성능, 실기기 모바일 키보드, 스크린리더, desktop/VS Code 실행은 이번에 별도 검증하지 않았다. 테스트용 브라우저 데이터와 SQLite는 사용자의 기존 작업 DB와 분리했다.

이 뷰어는 OpenAPI 전체 적합성 검증기나 API 실행기가 아니다. 상세 지원 범위와 제한은 [사용 가이드](../guides/openapi-block.md)를 따른다. 커밋과 푸시는 하지 않았다.
