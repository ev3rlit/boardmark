# Boardmark 제품 방향

2026-09-09 방향 갱신. 이 문서는 이전의 파일 원본·extension-first 우선순위를 대체한다.

> DB에 보관한 Markdown을 웹과 AI가 같은 정책으로 안전하게 편집하고, 캔버스로 탐색한다.

## 원본과 인터페이스

DB의 Markdown 원문 문자열이 단일 최종 원본이다. 문서 ID는 이름과 분리한다. AST·렌더링 모델·검색·태그·백링크는 재생성할 수 있는 파생 데이터이며 별도 편집 원본이 아니다. 중복 요청 기록·편집권 발급 정보·변경 이력은 보존해야 하는 운영 데이터다.

사람의 주 인터페이스는 웹 GUI, AI의 주 인터페이스는 CLI다. 둘 모두 같은 API의 저장·검증·충돌 방지 규칙을 사용한다. .md는 가져오기·내보내기 수단이다. 기존 파일을 자동 이동·삭제하거나 외부 수정으로 DB를 덮어쓰지 않는다.

## 함께 편집하는 경험

읽기·탐색·선택은 자유롭다. 실제 변경을 시작할 때 객체별 임시 편집권을 자동 획득한다. 같은 노트의 충돌 변경은 시작 전에 제한하고 독립 노트 변경은 최신 원문에 각각 적용한다. 다른 탭과 CLI는 같은 사용자여도 별개 세션이다. Markdown의 영구 locked 속성과 협업 편집권을 구분한다.

입력과 드래그의 로컬 반응은 즉시 처리하고 DB 저장 확정은 따로 표시한다. 마지막 저장 후 반납하고 끊긴 세션은 만료시킨다. 실패에서는 초안을 보존하며 의미를 알 수 없는 변경을 자동 덮어쓰지 않는다. Undo도 옛 문서 전체로 돌아가지 않는다.

FigJam은 원하는 사용감의 예시일 뿐 내부 구현이나 실제 잠금 정책을 추정하는 근거가 아니다.

## 현재 구현과 후속 범위

초기 구현은 로컬 단일 Node 서버와 SQLite, 웹, CLI다. 이는 구현 선택이며 사용자와 확정한 특정 DB 제품 요구사항은 아니다. 이유와 대안은 [설계 결정](../architecture/db-markdown-api.md)을 따른다.

desktop·VS Code의 파일 모드는 호환용으로 유지한다. 서버 문서와 파일 문서의 소유권은 분리하며 VS Code 미저장 버퍼를 서버 원본과 모호하게 결합하지 않는다.

기존 pack/renderer 확장 방향은 유지한다. 주변 UI의 반응형 배치가 객체 저장 좌표를 바꾸지 않는다. Vault 검색·태그·백링크·즐겨찾기·복구 이력 화면·첨부 정리·카메라 뷰·명령 팔레트·온보딩 확장은 후속 과제다. CRDT/OT, 양방향 파일 동기화, 다중 서버·클라우드 계정·결제는 이번 범위가 아니다.
